# Готовка: как сделать из сайта настоящее Android-приложение (APK)

Это готовый проект на базе **Capacitor**. Он упаковывает ваше приложение в настоящий Android-файл (APK) без установки Android Studio. Сборку делает бесплатный сервис **GitHub Actions**: вы загружаете файлы на GitHub и через несколько минут скачиваете готовый `.apk`.

> Для iPhone есть отдельный раздел в конце (часть 8). Коротко: для App Store нужны Mac и платный аккаунт Apple. Если этого нет, на iPhone приложение ставится прямо из браузера как веб-приложение (см. README в папке `gotovka`).

## 1. Что в папке

```
gotovka-app/
├─ www/                      ← само приложение (index.html, иконки)
├─ assets/                   ← картинки для иконки и заставки (из них делаются все размеры)
├─ capacitor.config.json     ← название приложения и его идентификатор
├─ package.json              ← список нужных библиотек
├─ .gitignore                ← что не загружать в репозиторий
├─ .github/workflows/
│   ├─ build-android.yml     ← сборка APK для установки (запускается сама)
│   └─ release-android.yml   ← сборка подписанных AAB и APK (запускается вручную)
└─ ИНСТРУКЦИЯ.md             ← этот файл
```

Папки `android/` в проекте нет. Её создаёт сборка на GitHub каждый раз заново, так что ничего поддерживать не нужно. Все изменения вы делаете только в `www/`.

**Идентификатор приложения** `com.gotovka.app` указан в `capacitor.config.json`. Он должен быть уникальным среди всех приложений в Google Play. Если планируете публикацию, замените его на свой, например `com.ivanov.gotovka` (латиница, строчные буквы, точки, без пробелов). После публикации менять его нельзя.

## 3. Загрузка проекта на GitHub

### 3.1. Создайте репозиторий
1. Войдите на GitHub, нажмите **+** справа сверху, затем **New repository**.
2. Имя: например `gotovka-app` (латиница, без пробелов).
3. Видимость: **Private** (приватный) подойдёт, сборка работает и в нём. Public тоже можно.
4. Галочки (README, .gitignore, license) не ставьте. Нажмите **Create repository**.

### 3.2. Загрузите файлы
Способ через браузер не умеет загружать скрытые папки (`.github`) так просто, поэтому есть два пути. Выберите один.

**Путь А. Через командную строку (надёжнее всего).**
Установите Git (https://git-scm.com), распакуйте архив, затем в терминале:

```bash
cd путь/к/папке/gotovka-app

git init
git add .
git commit -m "Приложение Готовка"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/gotovka-app.git
git push -u origin main
```

GitHub попросит войти. Вместо пароля нужен **токен**: GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token → отметьте `repo` и **`workflow`** (без `workflow` GitHub не примет файлы сборки) → скопируйте токен и вставьте вместо пароля.

**Путь Б. Через браузер.**
1. На странице пустого репозитория нажмите **uploading an existing file**.
2. Перетащите в окно файлы и папки `www`, `assets`, `capacitor.config.json`, `package.json`, `.gitignore`, `ИНСТРУКЦИЯ.md`. Нажмите **Commit changes**.
3. Папку `.github` браузер при перетаскивании часто пропускает, потому что она скрытая. Создайте файлы вручную: **Add file → Create new file**, в поле имени введите `.github/workflows/build-android.yml` (косые черты создадут папки сами), вставьте содержимое файла из архива, нажмите **Commit changes**. Повторите для `release-android.yml`.
4. Если в проводнике не видно `.github`, включите показ скрытых файлов (Windows: Вид → Показать → Скрытые элементы; Mac: Cmd+Shift+точка).

Проверка: в репозитории должна быть папка `.github/workflows` с двумя файлами.

## 4. Сборка APK и установка на телефон

### 4.1. Запустите сборку
Сборка стартует сама после загрузки файлов. Если не стартовала:
1. Откройте вкладку **Actions** в репозитории. Если GitHub просит разрешить запуск, нажмите зелёную кнопку.
2. Слева выберите **Сборка APK (для установки)**.
3. Справа **Run workflow**, затем зелёная **Run workflow**.

### 4.2. Дождитесь результата
Сборка длится 5–10 минут. Рядом с запуском вращается жёлтый кружок. Зелёная галочка означает успех, красный крестик означает ошибку (см. часть 10).

### 4.3. Скачайте APK
1. Нажмите на название завершённого запуска.
2. Внизу страницы в блоке **Artifacts** нажмите **Gotovka-APK**. Скачается zip-архив.
3. Распакуйте его, внутри файл `app-debug.apk`.

### 4.4. Установите на телефон
1. Перекиньте `app-debug.apk` на телефон (через кабель, почту, мессенджер или облако). Либо откройте страницу GitHub на самом телефоне и скачайте артефакт там.
2. Нажмите на файл на телефоне.
3. Android спросит разрешение на установку из неизвестного источника. Разрешите его для этого приложения (браузера или «Файлов»). Это нормально для приложений вне Google Play.
4. Нажмите **Установить**, затем **Открыть**.

Это тестовая (debug) версия. Она полностью рабочая, но не годится для Google Play. Для публикации нужна подписанная версия (часть 5).

## 5. Подписанная версия (для Google Play и раздачи другим людям)

Каждое приложение подписывается личным ключом. **Потеряете ключ или пароль, и обновлять опубликованное приложение будет нельзя.** Сохраните их в надёжном месте (облако + флешка) и никому не показывайте.

### 5.1. Создайте ключ (один раз)
Нужна Java (JDK 17 или новее): https://adoptium.net. В терминале:

```bash
keytool -genkeypair -v -keystore gotovka.jks -alias gotovka -keyalg RSA -keysize 2048 -validity 10000
```

Программа спросит пароль (придумайте и запомните), имя, организацию и т. д. (можно ответить кратко) и подтверждение. Получится файл `gotovka.jks`. В примере алиас ключа `gotovka`.

### 5.2. Превратите ключ в текст
**Mac / Linux:**
```bash
base64 -i gotovka.jks | tr -d '\n' > keystore.b64
```
**Windows (PowerShell):**
```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("gotovka.jks")) | Out-File -Encoding ascii -NoNewline keystore.b64
```
Содержимое файла `keystore.b64` нужно будет вставить в секрет.

### 5.3. Добавьте секреты в GitHub
Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**. Создайте четыре секрета с именами **ровно такими**:

| Имя секрета | Что вставить |
|---|---|
| `KEYSTORE_BASE64` | всё содержимое файла `keystore.b64` |
| `KEYSTORE_PASSWORD` | пароль от хранилища ключей |
| `KEY_ALIAS` | алиас ключа (в примере `gotovka`) |
| `KEY_PASSWORD` | пароль ключа (если при создании не просили отдельный, он такой же, как пароль хранилища) |

### 5.4. Запустите релизную сборку
1. **Actions → Релиз Android (подписанные AAB и APK) → Run workflow**.
2. **Номер сборки** (`version_code`): целое число. Для первого релиза `1`, для каждого следующего **обязательно больше предыдущего** (2, 3, 4…). Google Play не примет повтор.
3. **Версия** (`version_name`): то, что увидят пользователи, например `1.0.0`.
4. Нажмите **Run workflow**, дождитесь зелёной галочки и скачайте артефакт **Gotovka-release**. В нём два файла:
   - `Gotovka-release.aab`: для публикации в Google Play;
   - `Gotovka-release.apk`: для раздачи напрямую (друзьям, на сайте).

## 6. Публикация в Google Play

1. Зарегистрируйтесь в https://play.google.com/console (взнос 25 $, нужны документы для проверки личности).
2. **Создать приложение**: название «Готовка», язык, тип «Приложение», бесплатное.
3. Заполните обязательные разделы (Play Console ведёт по списку):
   - **Политика конфиденциальности.** Приложение ничего не собирает и не отправляет, все данные хранятся на устройстве. Страницу с таким текстом можно разместить бесплатно, например на GitHub Pages.
   - **Безопасность данных:** укажите, что данные не собираются и не передаются.
   - **Рейтинг контента**, **целевая аудитория**, **категория** (например «Еда и напитки»).
   - **Страница в магазине:** описание, иконка 512×512 (файл `www/img/icon-512.png`), скриншоты с телефона (минимум 2), графика 1024×500.
4. **Выпуск → Рабочая версия (или Закрытое тестирование) → Создать выпуск** и загрузите `Gotovka-release.aab`. Подпишите приложение через **Play App Signing** (предлагается по умолчанию, соглашайтесь).
5. Отправьте на проверку. Первая проверка занимает от нескольких часов до нескольких дней.

Важно: личные аккаунты разработчиков, созданные недавно, обязаны сначала пройти **закрытое тестирование** (обычно нужно 12 тестировщиков в течение 14 дней), и только потом открывается публикация для всех. Актуальные условия смотрите в Play Console, они меняются.

## 7. Как обновлять приложение

1. Замените файлы в `www/` (например, новый `index.html`).
2. Загрузите изменения на GitHub (`git add . && git commit -m "обновление" && git push` или через браузер **Add file → Upload files**).
3. Для тестовой версии сборка запустится сама. Для Google Play запустите **Релиз Android** с **номером сборки больше прежнего**.
4. В Play Console создайте новый выпуск и загрузите новый `.aab`.

Название и иконку меняйте так: имя приложения в `capacitor.config.json` (`appName`), картинки в папке `assets/` (`icon-only.png` и `icon-foreground.png`/`icon-background.png` по 1024×1024, `splash.png` 2732×2732). Остальные размеры создаются сборкой сами.

## 8. iPhone и App Store

Собрать приложение для iPhone можно только на **Mac с программой Xcode**, а публикация требует аккаунт Apple Developer за **99 $ в год**.

Если всё это есть:
```bash
npm install
npm install @capacitor/ios@^7.0.0
npx cap add ios
npx capacitor-assets generate --ios
npx cap sync ios
npx cap open ios
```
Дальше в Xcode: выберите свою команду разработчика (Signing & Capabilities), подключите iPhone или выберите симулятор, нажмите ▶. Для App Store: **Product → Archive → Distribute App**.

Если Mac или аккаунта нет, пользователям iPhone проще поставить приложение из Safari: открыть сайт (папка `gotovka`, GitHub Pages), нажать «Поделиться» → «На экран Домой».

## 9. Сборка на своём компьютере (по желанию)

Нужны: Node.js 20+, JDK 21, Android Studio.

```bash
cd gotovka-app
npm install
npx cap add android
npx capacitor-assets generate --android
npx cap sync android
npx cap open android      # откроется Android Studio
```
В Android Studio: **Build → Build Bundle(s) / APK(s) → Build APK(s)**. Либо запустите приложение на подключённом телефоне кнопкой ▶ (на телефоне включите «Отладку по USB»).

После изменений в `www/` выполняйте `npx cap sync android`.

## 10. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Во вкладке Actions пусто, сборка не запускается | Проверьте, что в репозитории есть `.github/workflows/build-android.yml` именно с такой вложенностью. Нажмите **Run workflow** вручную. Если Actions выключены: Settings → Actions → General → Allow all actions. |
| При `git push` ошибка про `workflow` scope | У токена нет права `workflow`. Создайте новый токен с галочками `repo` и `workflow`. |
| Сборка упала (красный крестик) | Откройте запуск, нажмите на упавший шаг и прочитайте последние строки лога. Самые частые причины ниже. |
| Ошибка `invalid source release: 21` или про версию Java | В обоих файлах workflows поменяйте `java-version: 21` на `17`, если ставите Capacitor 6, или оставьте 21 для Capacitor 7. Версия Java должна соответствовать версии Capacitor. |
| Ошибка на шаге `capacitor-assets` | Проверьте, что в `assets/` лежат все пять картинок с точными именами: `icon-only.png`, `icon-foreground.png`, `icon-background.png`, `splash.png`, `splash-dark.png`. |
| Ошибка `Не задан секрет …` | Секреты (часть 5.3) не созданы или имена написаны с ошибкой. |
| Телефон пишет «приложение не установлено» | Удалите ранее установленную версию (особенно если до этого стояла подписанная иначе) и поставьте заново. Тестовый (debug) и релизный APK подписаны разными ключами, поэтому поверх друг друга не ставятся. |
| Телефон блокирует установку | Разрешите установку из неизвестных источников для приложения, через которое открываете файл. |
| Текст заходит под системную строку сверху или снизу | На новых Android (15+) приложение рисуется во весь экран. Пришлите скриншот, и я подберу отступы. Обычно это решается добавлением отступов в `index.html`. |
| Сборка без изменений даёт разные результаты | Версии библиотек берутся «не ниже 7.0.0». Чтобы зафиксировать их, один раз выполните `npm install` на компьютере и загрузите созданный файл `package-lock.json` в репозиторий. |

## Важные замечания

- **Эту сборку я не мог запустить у себя**: в моей среде нет интернета, а скачать Android-инструменты без него нельзя. Файлы настроены по документации Capacitor, YAML и JSON проверены на корректность, а само приложение протестировано в браузере. Если первая сборка выдаст ошибку, скопируйте последние строки лога, и её легко исправить.
- Все данные пользователя (продукты, избранное, рацион, профиль) хранятся только на его телефоне. Приложению не нужны никакие разрешения Android.
- Калории и норма приблизительные и не заменяют консультацию врача.
